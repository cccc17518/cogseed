# 运行演示（examples/tech-review-walkthrough.md）

本示例演示 Skill 在材料齐全输入下的完整运行方式，以及各类被拒绝场景的处理，包含用户输入与预期输出。示例为原创虚构内容，仅用于演示。

## 场景一：正向（材料齐全，逐项校验）

### 用户输入

作业草稿：本课程设计实现一个基于Java控制台的学生成绩管理系统。
1. 系统主界面：使用while(true)循环展示菜单，用户输入0时通过break退出系统，输入其他数字则调用对应功能。
2. 数据存储：使用ArrayList<Student>存储全部学生信息与成绩，初始预置3条示例数据。
3. 分层结构：包含实体类Student、管理类StudentManager（封装addStudent、deleteStudent、updateStudent、queryStudent四个方法）、视图层StudentView、控制台入口类Main。
4. 功能实现：addStudent接收键盘输入新增学生，deleteStudent按学号删除，updateStudent按学号修改成绩，queryStudent按学号或姓名查询。
5. 代码规范：类名方法名使用驼峰命名，常量全大写，关键逻辑添加中文注释。

评分rubric：
1. 实现控制台循环菜单，输入0退出（25分）
2. 完成学生信息增删改查功能（30分）
3. 使用集合存储数据（20分）
4. 采用分层思想编写代码（25分）

课程额外要求：代码命名规范，添加注释。

### 预期输出

一、总体概览：作业覆盖了rubric全部4条评分项，功能完整、结构清晰，整体达标度较高。

二、逐项校验清单：
- 评分项1（循环菜单，输入0退出）：草稿第1条"使用while(true)循环展示菜单，用户输入0时通过break退出系统"——判定：满足。建议：可补充非法输入的处理分支说明。
- 评分项2（增删改查）：草稿第4条列出add/delete/update/query四个方法——判定：满足。建议：queryStudent同时支持学号或姓名，可补充查询不到时的返回处理。
- 评分项3（集合存储）：草稿第2条"使用ArrayList<Student>存储"——判定：满足。建议：无需修改。
- 评分项4（分层思想）：草稿第3条列出实体类/管理类/视图层/入口四层——判定：满足。建议：无需修改。

三、缺失信息与待确认问题：
- 未提供篇幅限制与提交格式，按不限制处理（默认假设）；
- 草稿未说明是否包含异常处理与输入校验，如评分要求涉及可补充说明。

## 场景二：反向（缺少 rubric，拒绝打分）
